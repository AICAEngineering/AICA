# Engineering process

AICA uses a staged, documentation-first process. The stages describe how future work should be evaluated; they do not assert that physical testing or prototype validation has occurred.

## 1. Documentation baseline

Record the concept boundary, intended question, assumptions, risks, and known unknowns. Establish what would count as useful evidence before added complexity is considered.

## 2. Model definition

Define a limited model or subsystem, expected behavior, instrumentation, operating conditions, safety boundaries, and acceptance criteria.

## 3. Controlled bench evaluation

If a model is authorized and feasible, record configuration, inputs, conditions, measurements, anomalies, and safety observations under controlled conditions.

## 4. Review and revision

Compare observations with the documented assumptions. Revise the model, method, or direction according to evidence. Preserve unsuccessful and inconclusive results.

## 5. Prototype decision and validation

Consider an integrated prototype only if earlier evidence justifies the added complexity and risk. Any later validation plan must define repeatability and limitations; neither progression nor technical success is guaranteed.
